## 蜗蜗的魔法序列

首先，交换和整体异或这两个操作如果交错进行的话是完全无法处理的，但显然它们是互不干扰的，而异或操作是可以结合的，因此题目转化为可进行一次整体异或，求逆序对加上异或次数（$0$ 或 $1$）的最小值。

对于 $n\le 2^{18}$，跑一遍 $\mathcal O(n\log n)$ 的统计逆序对是很快的，因此这道题目肯定不能只跑一次逆序对来简单求出。根据经验，异或是可以按位拆解的，因此可以考虑按照二进制位来贪心，这样子 $\mathcal O\left(n\log^2 n\right)$ 也是能过的，并且看起来更符合出题人的预期。

考虑如下的简单贪心：从高到低二进制位，将该位分别异或 $0$ 或者 $1$ 分别求逆序对数量，如果异或 $1$ 的逆序对数量 **严格小于** 异或 $0$ 的数量，那么该位异或 $1$ 一定不会劣。

### 正确性证明

对于该位的原始值，$0$ 的一堆会分在左边，$1$ 的一堆会分在右边。若该位异或上 $1$ 那么久相当于这两堆调换了顺序，然而堆内的逆序对数量是不变的，只会改变跨堆的逆序对数量。在处理下一位时，本位是 $0$ 的元素一定在 $1$ 的元素的左边，因此下一位只能改变堆内的贡献，因此跨对的贡献仅由该位决定。我们选择了跨堆贡献最少的异或方式，因此在不考虑异或那一次操作的情况下，该贪心方式是正确的。再考虑异或那一次操作，我们只会在异或 $1$ 逆序对数量严格小于 $0$ 时才异或 $1$，那么答案会因为这一位异或 $1$ 了而加一，或者之前已经异或了而不变。最坏的 $+1$ 情况下，由于是严格小于，因此最坏也是和异或 $0$ 答案相同，不会更劣。

**P.S.** 事实上从低到高位做也是对的，但结论的证明没这么简单。

```cpp
const LL kMaxN = (1 << 18) + 1;

LL tr[kMaxN], a[kMaxN], n, ans;

void modify(LL x) {
  for (x++; x; x -= x & -x) {
    tr[x]++;
  }
}

LL query(LL x) {
  LL res = 0;
  for (x++; x < kMaxN; x += x & -x) {
    res += tr[x];
  }
  return res;
}

int main() {
  cin.tie(0)->sync_with_stdio(0);
  cin >> n;
  for (LL i = 0; i < n; i++) {
    cin >> a[i];
  }
  for (LL i = 17; i >= 0; i--) {
    LL s0 = 0, s1 = 1;
    fill(tr + 1, tr + kMaxN, 0);
    for (LL j = 0; j < n; j++) {
      s0 += query(a[j]);
      modify(a[j]);
    }
    fill(tr + 1, tr + kMaxN, 0);
    for (LL j = 0; j < n; j++) {
      s1 += query(a[j] ^ (1 << i));
      modify(a[j] ^ (1 << i));
    }
    if (s1 < s0) {
      for (LL j = 0; j < n; j++) {
        a[j] ^= 1 << i;
      }
      ans |= 1;
    }
  }
  fill(tr + 1, tr + kMaxN, 0);
  for (LL i = 0; i < n; i++) {
    ans += query(a[i]);
    modify(a[i]);
  }
  cout << ans << '\n';
  return 0;
}
```

## 蜗蜗的灵脉地图

初次看到这题时，发现居然要求一个图的最短路奇偶矩阵为给定值，沃趣居然这么难，而且必须 $\mathcal O\left(n^2\right)$ 算，这咋办？

观察样例并手推，~~加上代码源先前多次出诈骗题的经历~~，不难提出猜想：若输入矩阵有解，那么将该矩阵视为邻接矩阵，对应的图本身一定是解之一。

然后觉得这个结论太简单了，看起来就不太对，但是却一直提不出 Hack，大样例也都能过，所以就默认他是对的。现在我们的问题就是如何判断无解，即原图的最短路奇偶矩阵是否为它本身。

显然我们可以 BFS 求，但是该图为稠密图，复杂度 $\mathcal O\left(n\cdot n^2\right)$ 直接爆炸。Floyd 倒是可以用 BitSet 优化至 $\mathcal O\left(\cfrac{n^3}{w}\right)$，但是那个是跑传递闭包的，根本不是奇偶最短路。

后面再猜测，若不连通一定无解，然后就被 Hack 掉了：四个点一条链，联通但是 $1\rightarrow 4$ 最短路为奇数，可原图当中 $a_{1,4}=0$，就挂了。

实际上结论很简单，使我瞎尝试出来的：对于任何 $a_{i,j}=0$，需要满足存在 $k$ 使得 $a_{i,k}=a_{k,j}=1$。直观上很简单，这样子可以保证图基本的联通，但是要求最短路为偶数的两条边必须能够被拆成两条长度为 $1$ 的路径。上面的 Hack 就没用了。

性感的证明是首先 $a_{i,j}=1$ 那显然满足条件，最短路为 $1$。若 $a_{i,j}=0$，且存在一个 $k$ 有 $a_{i,k}=a_{k,j}=1$，那么 $i\rightarrow j$ 距离为 $2$，也是满足条件的。那没有最短路大于 $2$ 的情况吗？不存在，因为假设存在长度为 $3$ 的最短路，那么这两点间会因为最短距离为奇数而直接连起来，因此最短路没有超过 $2$ 的。

### 严谨的证明

- **充分性**：在 $G$ 中，$a_{i,j}=1$ 相当于有边，$i\rightarrow j$ 最短路自然为 $1$ 奇偶性对；$a_{i,j}=0$ 但有 $a_{i,k}=a_{k,j}=1$ 说明没边但有长 $2$ 路径，奇偶性也对，因此 $G$ 是一个解，如果有解的话。
- **必要性**：若某个图 $H$ 实现了矩阵 $A$，若 $a_{i,j}=0$ 则 $(i,j)$ 在 $G$ 中必有长 $2$ 路径。证明：$H$ 中 $d(i,j)$ 是偶数且至少为 $2$。取 $H$ 中 $i\rightarrow j$ 的一条最短路，设第一步走到 $x$，因为 $d_H(i,x)=1$，所以 $a_{i,x}=1$；又因为 $x$ 在 $i\rightarrow j$ 的一条最短路上，所以 $d_H(x,j)$ 是奇数，所以 $a_{x,j}=1$。这个 $x$ 就是 $G$ 里 $(i,j)$ 的共同邻居。

---

因此，我们只需要使用 BitSet 判断对于 $a_{i,j}=0$，能否通过某个中转点 $k$ 从 $i$ 两步到达 $j$ 即可。若成功直接输出原图。

```cpp
const int kMaxN = 2005;

int t, n;
bitset<kMaxN> a[kMaxN], b[kMaxN];
vector<pair<int, int>> v;
char c;

int main() {
  cin.tie(0)->sync_with_stdio(0);
  for (cin >> t; t; t--) {
    cin >> n;
    for (int i = 1; i <= n; i++) {
      a[i].reset();
      b[i].reset();
      for (int j = 1; j <= n; j++) {
        cin >> c;
        a[i][j] = c - '0';
      }
    }
    for (int i = 1; i <= n; i++) {
      for (int j = 1; j <= n; j++) {
        if (a[i][j]) {
          b[i] |= a[j];
        }
      }
    }
    [&]() {
      for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= n; j++) {
          if (i != j && !a[i][j] && !b[i][j]) {
            cout << "NO\n";
            return;
          }
        }
      }
      cout << "YES\n";
      v.clear();
      for (int i = 1; i <= n; i++) {
        for (int j = i + 1; j <= n; j++) {
          if (a[i][j]) {
            v.emplace_back(i, j);
          }
        }
      }
      cout << v.size() << '\n';
      for (auto [i, j] : v) {
        cout << i << ' ' << j << '\n';
      }
    }();
  }
  return 0;
}
```

## 魔法材料整理

首先，我们总是合并相邻的一块，否则不优。假设已经选好了 $a$，令 $g_i=a_{i+1}-a_i$，那么对于每一块相邻的，我们可以选择花费 $D$ 不合并，或者花费 $g_i$ 少一块，那么自然有答案等于 $D+\sum\limits_{i=1}^{n-1}\min(D, g_i)$。

事实上只需要枚举 $g$ 序列即可，约束有 $a_1\le 1$ 且 $a_1+\sum\limits_{i=1}^{n-1}g_i\le M$。

既然有 $\min$，那么我们得要将其拆开。设恰好有 $i$ 个 $g$ 大于等于 $D$，这些就是取 $D$ 的，另外 $n-1-i$ 个就是取它自己的值。首先，这 $i$ 个大于等于 $D$ 的可以放在不同的位置组合上，即 $\dbinom{n-1}{i}$ 种方案。

对于剩下 $r=n-i-1$ 个小于 $D$ 的，由于 $i$ 个大于等于 $D$ 的为答案贡献了 $(i+1)\cdot D$，因此这些数的和必须是 $k-(i+1)D$，并且每个数的取值范围是 $[0,D)$。这是有上界隔板计数，可以通过容斥（二项式反演）求出。令 $\beta(j)$ 表示指定 $j$ 个变量至少为 $D$，其余随便选的方案，显然令 $\alpha(j)$ 表示恰好有 $j$ 个大于等于 $D$ 的，那么 $\beta(j)$ 是 $\alpha(j)$ 的二项式正变换。通过二项式反演可得

$$
\alpha(0)=\sum\limits_{j=0}^r(-1)^j\binom{r}{j}\beta(j)=\sum\limits_{j=0}^r(-1)^j\binom{r}{j}\binom{s-jD+r-1}{r-1}
$$

大于大于等于 $D$ 的，每个写成 $D+e$ 的形式，记超额总和为 $E=\sum e$，此时总跨度为 $G=K-D+E$，所以 $a_i$ 可选个数为 $M-G=M-K+D-E$，记 $L=M-K+D$，那么大于等于 $D$ 元素值分配和 $a_i$ 的分配合起来的方案数就是

$$
\sum_{E=0}^L \binom{E+i-1}{i-1}(L-E)=\binom{L+i}{i+1}
$$

因此全部合起来就是

$$
\text{ans}=\sum_{i=0}^{n-1}\binom{n-1}{i}\left[\sum\limits_{j=0}^r(-1)^j\binom{r}{j}\binom{s-jD+r-1}{r-1}\right]\binom{M-K+D+i}{i+1}
$$

其中 $r=n-i-1$.

时间复杂度 $\mathcal O(n^2)$。

```cpp
const LL kMaxN = 3e6 + 5, kMod = 998244353;

LL fac[kMaxN], inv[kMaxN], t, n, m, d, k;

LL pow(LL a, LL b) {
  LL res = 1;
  for (; b; b /= 2) {
    b % 2 && (res = res * a % kMod);
    a = a * a % kMod;
  }
  return res;
}

void preprocess() {
  fac[0] = 1;
  for (LL i = 1; i < kMaxN; i++) {
    fac[i] = fac[i - 1] * i % kMod;
  }
  inv[kMaxN - 1] = pow(fac[kMaxN - 1], kMod - 2);
  for (LL i = kMaxN - 2; i >= 0; i--) {
    inv[i] = inv[i + 1] * (i + 1) % kMod;
  }
}

LL comb(LL n, LL m) {
  return m > n || m < 0 ? 0 : fac[n] * inv[n - m] % kMod * inv[m] % kMod;
}

// 将 n 分成 m 份，每份 < D
LL calc(LL n, LL m) {
  if (!m) {
    return !n;
  }
  LL res = 0;
  for (LL i = 0; i <= m && i * d <= n; i++) {
    res = (res + (i % 2 ? -1 : 1) * comb(m, i) * comb(n - i * d + m - 1, m - 1) % kMod) % kMod;
  }
  return (res + kMod) % kMod;
}

int main() {
  cin.tie(0)->sync_with_stdio(0);
  preprocess();
  for (cin >> t; t; t--) {
    cin >> n >> m >> d >> k;
    LL ans = 0;
    for (LL i = 0; i < n; i++) {
      ans = (ans + comb(n - 1, i) * calc(k - i * d - d, n - 1 - i) % kMod * comb(m - k + d + i, i + 1) % kMod) % kMod;
    }
    cout << ans << '\n';
  }
  return 0;
}
```
